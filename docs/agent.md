# mycode-agent

没有界面的代理运行时，里面是两层，互不依赖。

1. **循环**。`Agent::prompt` 对着内存里的历史跑，可以完全没有磁盘。
2. **会话账本**。宿主把已经发生的事件写成可恢复的日志。宿主自己的任务运行时驱动它。

它们放在一个 crate 里，是因为一次对话只对应一份持久历史。工作区里没有「只要循环不要账本」或反过来的第二个调用方。

## 循环

```text
prompt(用户消息)
  消息进入历史，发出 TurnStarted
  loop
    钩子可以改写即将发出的 Request（生产环境用它压缩历史）
    provider 流式输出，增量作为 AgentEvent 广播
    只有完整的助手消息进入历史
    对每个工具调用：观察者先跑，然后分发，结果写回历史
  直到模型不再调用工具
  TurnEnded(Completed 或 Aborted)
```

`TurnEnv` 注入这一回合的一切：provider、注册表、钩子、取消令牌、事件总线、工作目录。循环不打开 `secrets.json`，也不创建会话目录。

取消是调用方令牌的子令牌。触发后，进行中的流以取消结束，半截助手消息丢弃，`prompt` 返回 `Aborted`。工具里的 panic 被接住，变成该次调用的错误结果，不把回合任务冲垮。

`HookRunner` 上生产环境只装请求前钩子：改写 `Request`，应用层在这里做自动压缩。没有工具前观察者，回合也不会在改文件之前做快照。

`build_system_prompt` 用固定的身份说明、工具使用约定，加上注册表里每个工具的一句说明。注册表里没有的名字不会出现在提示里。约定里 `write`、`edit` 和 `shell` 都可以改文件。文件编辑走 `shell` 的 `mode` `script`：POSIX shell 用 Python 的引号 heredoc 或短脚本，PowerShell 用 here-string 管道给 `python`。`mode` `program` 不经过 shell，只启动一个可加载映像。编辑或撤回一条对话不会恢复或删除工作区文件。

## 会话账本

一个会话一个目录 `sessions/<ses1-id>/`：

| 路径 | 作用 |
| --- | --- |
| `manifest.json` | 分支头、事件条数、已提交字节数。这是提交权威，原子替换 |
| `branches/<br1-id>.events` | 只追加的帧。每帧带载荷摘要 |
| `pending/<evt1-id>.payload` | 提交前的暂存。期望头对上之后才被追加消费，一次有效 |
| `compaction.json` | 和账本放在一起，由 `mycode-config` 读写 |

已提交前缀的长度以清单为准。崩溃留下的日志尾巴在恢复时丢掉。已提交区间里摘要不符或结构坏了，则整次打开失败（fail closed）。单会话日志合计上限 512 MiB，单条载荷 8 MiB，清单 64 KiB。

写路径是：在期望头上预留 → 载荷落到 `pending/` → 追加并推进清单。头已被别人推进时，这次预留作废。界面上的「发送」和「撤回」都带上一次看到的头，过期就返回「已经向前走了」，而不是默默覆盖。

分支可以分叉和回退到某条事件。读是按页的，单次有条数上限。恢复按块校验，大约每次 1 MiB，并先报告 `recovering` / `replaying`，再执行这次请求的动作。

列表走 `inspect_sessions`：每个清单独立解码，不在列表时做恢复。目录在但清单读不出的会话进 `corrupt` 列表，调用方可以删掉它。只有会话根目录本身读不了，列表才整体失败。

删除时，服务先丢掉该会话的内存账本，避免在途写入把刚删的目录再造出来。和界面、取消的配合在 `mycode-app`。

## 运行时为什么这么重

账本写入经过一个会话 actor：准入、暂存、分块拉取、动作分发。动作在阻塞线程池上碰磁盘，调用方的异步运行时不被 `block_on` 占住。generation fence 保证「发布这一代」和「卸下这一代」不会和仍在进行的活动交错——删除会话时需要这个，否则半次提交会留下一个永久报错的目录。

账本是单写者。调用方看到的就是上面的预留、追加和期望头。

## 不放在这里的东西

选模型、拼 MCP、压缩用的那次摘要请求、把账本投影成聊天气泡，都在 `mycode-app`。循环只消费已经准备好的 `TurnEnv`。
